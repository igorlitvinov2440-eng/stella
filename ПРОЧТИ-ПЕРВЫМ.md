## 1. Что это за приложение

**Стелла** — настольный ИИ-компаньон на Electron (Windows). Живёт вместо рабочего
стола: окно лежит фоном поверх обоев, поверх него работают обычные программы.
Внутри: чат с ИИ, голос (три движка синтеза + распознавание), задачи и напоминания,
макросы, запуск программ, журнал действий, тема и фон.

Владелец — Игорь, общается по-русски. Отвечать ему нужно **по-русски**.

**Приложение используется только развёрнутым на весь экран** (2560×1410). Интерфейс
делается сразу под полный экран, уменьшенное окно не рассматривается.

## 3. Как запустить

```powershell
cd код
npm install          # ставит Electron и electron-builder (нужен интернет)
npm start            # запуск в режиме разработки
npm run pack:win     # сборка: код\dist-new\win-unpacked\Stella.exe
```

Требуется Node.js. На машине Игоря стоит Electron 33.4.11.

**Важно:** `npm start` и сборка работают с **разными папками данных** (см. ловушку 1).
Поэтому вид проверяем на сборке, а не в режиме разработки.

## 4. Как устроен код

- `код\stella-prototype.html` — **весь интерфейс в одном файле** (~850 КБ): разметка,
  стили, логика. Правится текстовыми заменами.
- `код\electron\main.js` — окно, режим подложки, IPC, работа с данными.
- `код\electron\preload.js` — мост между окном и системой (`window.stellaDesktop`).
- `код\electron\asr-local.js`, `tts-local.js`, `tts-eleven.js`, `tts-fish.js` — голос.
- `код\electron\telegram-bot.js` — управление из мессенджера.
- `код\electron\files-index.js` — индекс файлов для поиска.
- `код\scripts\` — сборка и мелочи (иконка, синхронизация библиотек).

Внутри HTML файл разбит на пронумерованные разделы (`/* --- 1. ... --- */`).
Стили лежат в двух местах: обычный `<style>` в начале и большой блок, который
вставляется из JavaScript (`document.head.insertAdjacentHTML(...)`).

## 5. Порядок работы, который показал себя лучше всего

1. Сохранить копию интерфейса: `stella-prototype.html` → `stella-prototype.backup-<что-меняем>.html`.
2. Написать скрипт правки `patch-<тема>.py`: он читает файл, делает **точные текстовые
   замены** и падает с сообщением, если строка не найдена ровно один раз.
3. Запустить `python инструменты\check-js.py` — он разбирает все скрипты страницы и
   скажет, если синтаксис сломан. **Это обязательный шаг перед сборкой.**
4. Собрать: `npm run pack:win`.
5. Запустить `код\dist-new\win-unpacked\Stella.exe`, снять снимок окна
   (`инструменты\shot-hud.ps1`), посмотреть глазами, показать Игорю.

Так сделаны все правки в `история-правок\` — там же видно стиль замен и вспомогательные
функции (учёт переводов строк `\n` и `\r\n`, проверка единственного совпадения).

## 6. Ловушки (каждая стоила времени — не наступайте снова)

1. **Разработка и сборка используют разные папки данных.** Сборка читает
   `C:\Stella\Стелла-данные` (настройки Игоря), а `npm start` — папку рядом с
   Electron внутри `node_modules`, пустую и со стандартными настройками. В режиме
   разработки вы не увидите ни задач, ни телеметрии, ни выбранного фона — и легко
   примете это за ошибку в коде. **Вид проверять только на сборке.**
2. **Обратные кавычки в блоке стилей ломают приложение.** Большой блок CSS лежит
   внутри шаблонной строки JavaScript. Кавычка (даже в комментарии) обрывает строку —
   приложение собирается, но открывается с пустым экраном. Проверяйте `check-js.py`.
3. **Анимация сильнее обычного правила.** Если в кадрах анимации задан `transform`,
   он перебивает `transform` из правила, и разворот/наклон панели просто не работает.
   Анимировать появление только через `opacity`, а повороты задавать обычным правилом.
4. **`backdrop-filter` вместе с 3D-поворотом** заставляет Chromium не рисовать элемент
   вовсе — панель исчезала целиком, хотя была в разметке. Размытие подложки с 3D
   не совмещать.
5. **Одна перспектива на колонку, а не на панель.** `transform: perspective(...)`
   у каждой панели даёт каждой свою точку схода — панели одной колонки выглядят
   рассогласованно. Перспектива задаётся на контейнер (`perspective: 2200px` на `.rail`).
6. **PowerShell 5.1 читает `.ps1` как ANSI.** Русские буквы внутри такого скрипта
   ломают разбор. Русский текст держать в отдельном UTF-8 файле.
7. **Не вставлять JSON прямо в командную строку PowerShell** — он съедает кавычки.
   Сложные скрипты писать файлом и запускать `python файл.py`.
8. **Не закрывать программы Игоря силой.** Только вежливое закрытие окна
   (`CloseMainWindow`), затем пауза. Перед сборкой приложение должно быть закрыто.
9. **В `state.json` лежат ключи Игоря** (Fish Audio и прочее) — их не копировать,
   не пересылать и не выкладывать.
10. **Два окна приложения одновременно** писать в одни данные — не запускать
    сборку и режим разработки одновременно.

## 8. Чего хочет Игорь (стиль работы)

- Интерфейс копируем **с образца**: сначала внешний вид панели, потом содержимое.
- Панели должны быть ближе к краям и выше; поля по вертикали можно тянуть.
- Отвечать по-русски, коротко, по делу; показывать результат снимком экрана.
- Не спрашивать разрешения на каждый шаг — делать и показывать.
